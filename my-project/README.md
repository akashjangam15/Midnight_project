# my-project — a Midnight counter with an explicit public/private line

A Compact smart contract plus its TypeScript tooling, built to demonstrate the one
thing that makes Midnight different from a plain blockchain: **you choose what is
public**. This contract keeps its inputs secret, publishes only aggregates, and
makes every disclosure a single auditable call.

- **Contract:** `contracts/counter.compact` — 3 circuits, 3 public ledger fields, 2 private witnesses
- **Tests:** 5 unit tests, no network required (~2s)
- **Network:** Midnight `preview`
- **Toolchain:** Compact compiler `0.31.1`, Midnight.js `4.1.1`, Node ≥ 22

---

## What is public and what is private

| Declared                                 | Visibility | Where it lives                      |
| ---------------------------------------- | ---------- | ----------------------------------- |
| `ledger count: Uint<32>`                 | **PUBLIC** | on-chain state, readable by anyone  |
| `ledger updateCount: Uint<32>`           | **PUBLIC** | on-chain state, readable by anyone  |
| `ledger publishedMessage: Opaque<"string">` | **PUBLIC** | on-chain state, empty until disclosed |
| `witness privateStep(): Uint<32>`        | **PRIVATE** | local encrypted private state      |
| `witness privateMessage(): Opaque<"string">` | **PRIVATE** | local encrypted private state   |

**Circuits**

| Circuit            | Effect on chain                                            | Discloses            |
| ------------------ | ---------------------------------------------------------- | -------------------- |
| `increment()`      | `count += privateStep()`, `updateCount += 1`                | the **sum**, not the step |
| `publishMessage()` | `publishedMessage = privateMessage()`                       | the note verbatim    |
| `reset()`          | `count = 0`, `updateCount = 0`                              | nothing private      |

**Why `disclose()` matters.** The Compact compiler's disclosure analysis will not
let a witness-derived value flow into public state without an explicit
`disclose()`. Every place private data becomes public is therefore a greppable
call — there are exactly two, and both are inside circuits whose names state what
they publish. That is the whole privacy story of this contract, and
`tests/counter.test.ts` asserts it rather than trusting it:

- the raw bytes of the private note are **absent** from the encoded public state
  until `publishMessage()` is called, and present after;
- the private step's own cell encoding never appears in the public state, even
  though the running total (its sum) does;
- the public ledger exposes exactly the three declared fields — no witness is
  part of the public state.

A witness call is evaluated locally while the proof is built. Only the proof is
submitted, so the chain learns that "the result is correct given *some* private
input" and nothing about the input itself.

## Requirements

- **Node ≥ 22**
- **Compact compiler** — `compact update 0.31.1` (this project is pinned to the
  version the Midnight.js 4.1.1 toolchain expects)
- **Docker** — for the local proof server (`npm run proof-server:start`). Proofs
  are generated by the proof server even when deploying to a public network.
- **tNIGHT + DUST** for a public network: the deploy script prints the wallet
  address and waits for the faucet.

## Commands

```bash
npm run compile                          # compact compile → managed/counter
npm test                                 # 5 unit tests, no network needed
npm run build                            # tsc --noEmit

npm run proof-server:start               # docker compose up -d (proof server)
npm run deploy -- --network preview      # compile-ready artifacts → deploy
npm run cli                              # interact with the deployed contract
npm run check-balance -- --network preview
npm run network preview                  # set/show the active network
npm run test:e2e                         # read-only check against the deployment
npm run clean                            # delete managed/, state file, wallet cache
```

`npm run setup -- --network <net>` runs the whole first-time flow: compose up →
compile → deploy.

### Environment variables

| Variable                    | Used by        | Default                                  |
| --------------------------- | -------------- | ---------------------------------------- |
| `COUNTER_STEP`              | deploy         | `1` — initial **private** step           |
| `COUNTER_MESSAGE`           | deploy         | `counter deployed from my-project` — initial **private** note |
| `PRIVATE_STATE_PASSWORD`    | deploy/cli     | a local-devnet placeholder (≥16 chars)   |
| `MIDNIGHT_FAUCET_TIMEOUT_MS`| deploy         | `600000` (10 min funding wait)           |
| `MIDNIGHT_WALLET_MNEMONIC`  | all            | unset — use the wallet in `.midnight-state.json` |

`COUNTER_STEP` / `COUNTER_MESSAGE` set *private* state. Changing them changes
nothing on chain — the deployed ledger still starts at `count = 0`.

## Testing

`npm test` runs the compiled contract directly against `compact-runtime` — no
wallet, no node, no proof server, no network:

| Test | What it proves |
| ---- | -------------- |
| `increment() adds the private step to the public count` | circuit logic: `count` and `updateCount` advance as declared |
| `increment() refuses a non-positive private step` | the on-chain `assert` aborts the call and leaves no partial state |
| `publishMessage() … reset() …` | state transitions: disclosure persists, `reset()` clears only the counters, private state survives |
| `private inputs are never exposed in the public ledger state` | privacy: field-by-field and raw-bytes assertions described above |
| `private state is JSON-serializable and fits Uint<32>` | deploy hygiene: see the note below |

> **Note on private state and `bigint`.** The Midnight.js private-state provider
> `JSON.stringify`s private state, which throws on `bigint`. `src/witnesses.ts`
> therefore stores `step` as a `number` and converts to `bigint` at the circuit
> boundary. A `bigint` in private state fails at deploy time, not at compile
> time — the last test exists to catch it locally.

Practically: `compact compile` shows one artefact per circuit. If it doesn't
compile, nothing else here will run.

| Deployed at | 2026-09-21T10:06:14Z |

The deploy was verified by reading the on-chain state back through the indexer:
`count = 0`, `updateCount = 0`, `publishedMessage = ""` — a public ledger that says
nothing about the private step or note it was deployed with.

A deploy is **not** upgradeable: the address is derived from the contract's
initial state, so editing `counter.compact` and redeploying produces a *new*
address. The old instance keeps its last state forever. (Midnight has an
opt-in maintenance-authority mechanism for upgradeable contracts; this one does
not use it.)

`npm run deploy` overwrites `deployments.preview.address`, so record the old
address elsewhere before redeploying if you still need it. Because the address is
public while the private state is local, a *redeploy* starts with an empty
private state — set it before calling any circuit.

## Notes for anyone running this in WSL

- Contract logic tests are fast because they never touch the wallet SDK.
  Anything that *does* (`deploy`, `cli`, `check-balance`) imports `effect`
  transitively in the Midnight.js dependency chain, which can take minutes to
  load on some filesystems before any sync starts. Budget for it, and prefer
  detached runs for long commands.
- Wallet sync state is cached in `.midnight-wallet-state/`. A sync only persists
  after it completes, so an interrupted `deploy` restarts from genesis.
